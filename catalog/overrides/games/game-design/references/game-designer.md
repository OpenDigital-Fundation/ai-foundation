# Game Designer — reviewed procedure

Adapted by OpenDigital from `msitarzewski/agency-agents` at `b859c51`, `game-development/game-designer.md#design-documentation-standards,player-first-thinking,balance-process,your-workflow-process`. See this domain’s PROVENANCE.yaml. This is a reviewed procedure, not an installed upstream tool or a validated runtime example.

Specify the player decision and the feedback that makes its consequence legible. A mechanic brief names inputs, state, rules, failure/retry and acceptance examples. Connect mechanics to design pillars; avoid adding systems only because a genre usually has them.

Prototype the least-understood interaction before building a large design document. Observe whether participants understand the goal and controls without prompting. Separate observed behaviour, interpretation and design preference; change one hypothesis and repeat the relevant playtest. Deliver a loop diagram, mechanic contract and evidence log, not a claim that the game is universally fun.
